Modbus TCP

LED_O is controlled through Modbus TCP using a zero-based register map (0-99).

Function Codes (Hex)

  • 01 - Control-bit operation used by this firmware profile.
  • 03 - Read display-related register values (0-99).
  • 06 - Write one holding register (single value update).
  • 10 - Write multiple holding registers (block update).

Note: This implementation targets the control/read behavior used by the LED_O firmware profile.

Register Addressing

All addresses on this page are zero-based (0-99).
Use direct zero-based addressing for this device; 40000-style addressing is not used.

Control Register Map


  • 0 - 3: [XStart, YStart, XEnd, YEnd].
    • Defines geometry bounds in pixels for shapes and motion paths.
    • Typical sequence: set these first, then send shape/style registers.
  • 4 - 7: [Shape, Quantity, Weight, Color].
    • Shape - 0 = Rectangle, 1 = Triangle, 2 = Circle, 3 = Segment Line, 4 = Line.
    • Quantity - Repeat count; practical max depends on width and spacing.
    • Weight - Edge/line thickness in pixels.
    • Color - RGB565 color value (16-bit: R5/G6/B5).
  • 8 - 9: [Bitmap, Quantity]
    • Bitmap - Bitmap index from installed assets.
    • Quantity - Repeat count constrained by display width and bitmap width.
  • 10 - 11: [Border Weight, Border Color]
    • Border Weight - Top and bottom band thickness in pixels.
    • Border Color - RGB565 color value.
  • 12 - 15: [Text XPos, Text YPos, Text Color, Font Type]
    • Text XPos / YPos - Text anchor position in pixels.
    • Text Color - RGB565 color value.
    • Font Type - Font selector index/value.
  • 16 - 17: [SI Unit, Decimal Place].
    • SI Unit - Index into unit list: ["*C","*F","g","Kg","T","ml","l","%","ms","mm","rpm"].
    • Decimal Place - Numeric precision for formatted values (recommended max: 4).
  • 18 - 23: [LO Limit, HI Limit, Alarm LO, Alarm HI, Alarm LO Color, Alarm HI Color].
    • Defines graph scaling and threshold-based alarm color behavior.
  • 24 - 25: [Rotation Direction, Rotation Speed].
    • Direction - 0 = left-to-right, 1 = right-to-left.
    • Speed - Frame-delay control. 0 disables rotation; 1 is fastest.
  • 26 - 27: [Fill Screen, Fill Color].
    • Fill Screen - 0 = off, 1 = on.
    • Fill Color - RGB565 color value.
  • 28: [Text Marquee Gap].
    • Text Marquee Gap - Pixel spacing inserted between repeats of long scrolling text.
    • Use lower values for tighter loops and higher values for clearer separation.
  • 29: [Reserved].
  • 30 - 59: [Text].
    • Text - Message payload area.
    • Current firmware path supports up to 59 visible characters plus null terminator safety.
  • 60 - 79: [Integer Values].
    • Integer - Integer holding-value area; primary displayed value starts at register 60.
  • 80 - 89: [Real Values].
    • Read/Write - Real-value area; primary displayed value starts at register 80.
  • 90 - 99: [Real Values].
    • Read-Only - Reserved for extended/status use.

Recommended Write Sequence

  • Set geometry first (0-3), then style/color (4-7), then motion/fill/text options.
  • Use 06 for low-frequency single-register edits and 10 for grouped updates that must stay coherent on screen.
  • For text updates, write properties (12-15 and 28), then write payload (30-59).
  • Use rotation speed 0 when staging a multi-step update if you want to avoid visible in-between frames.

PLC Integration Notes

  • Treat this as a zero-based holding-register map in your PLC tag layer.
  • For deterministic scan behavior, group related writes into one FC10 transaction whenever possible.
  • If your PLC uses 40001-style addressing, apply your driver offset so it targets register 0-99 on this device.
