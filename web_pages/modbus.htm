Modbus TCP

LED_O is controlled through Modbus TCP using a zero-based register map (0-99). This page is designed for quick PLC implementation and commissioning reference.

Function Codes (Hex)

  • 01 Read control-bit registers 0-1 (2 bytes / 16 bits in this firmware profile).
  • 03 Read holding registers 0-99.
  • 04 Read input registers 0-99.
  • 06 Write one holding register (single value update).
  • 10 Write multiple holding registers 0-99 (block update).

Note: This implementation targets the control/read behavior used by the LED_O firmware profile.

Register Addressing

All addresses on this page are zero-based (0-99).
Use direct zero-based addressing for this device; 40000-style addressing is not used.

Control Register Map

Control Bit Registers (FC01 Read, FC05/FC15 Write)

Control bits are organized in two bytes (register 0 and register 1). Bit order is shown from 7 (left) to 0 (right).

Control Byte 0 (register 0)

Orientation control: write byte1 bit3 = 1 for upside-down (180), or 0 for normal orientation.

0 - 3: Geometry XStart/YStart/XEnd/YEnd
  • Defines geometry bounds in pixels for shapes and motion paths.
  • Typical sequence: set these first, then send shape/style registers.
4 - 7: Shape Style Shape/Quantity/Weight/Color
  • Shape - 0 = Rectangle, 1 = Triangle, 2 = Circle, 3 = Segment Line, 4 = Line.
  • Quantity - Repeat count; practical max depends on width and spacing.
  • Weight - Edge/line thickness in pixels.
  • Color - RGB565 color value (16-bit: R5/G6/B5).
8 - 11: Bitmap and Border Bitmap/Quantity/Border
  • 8 - 9: Bitmap index and repeat count constrained by display width and bitmap width.
  • 10 - 11: Border weight (top/bottom band thickness) and border color (RGB565).
12 - 17: Text and Units Text Pos/Color/Font/SI
  • 12 - 15: Text XPos, Text YPos, Text Color, Font Type.
  • 16 - 17: SI Unit index and Decimal Place precision.
  • SI Unit list: ["*C","*F","g","Kg","T","ml","l","%","ms","mm","rpm"].
18 - 29: Limits, Rotation, Fill, Marquee Gap Alarms/Motion/Fill
  • 18 - 23: Graph scaling and threshold-based alarm colors.
  • 24 - 25: Rotation Direction and Rotation Speed (0 disables rotation; 1 fastest).
  • 26 - 27: Fill Screen (0/1) and Fill Color (RGB565).
  • 28: Text Marquee Gap, pixel spacing between long-scroll repeats.
  • 29: Reserved.
30 - 99: Text Payload and Numeric Values Text/Integers/Reals
  • 30 - 59: Text payload area (supports up to 59 visible characters plus null terminator safety).
  • 60 - 79: Integer holding-value area; primary displayed value starts at register 60.
  • 80 - 89: Read/write real-value area; primary displayed value starts at register 80.
  • 90 - 99: Read-only area reserved for extended/status use.

Recommended Write Sequence

  • Set geometry first (0-3), then style/color (4-7), then motion/fill/text options.
  • Use 06 for low-frequency single-register edits and 10 for grouped updates that must stay coherent on screen.
  • For text updates, write properties (12-15 and 28), then write payload (30-59).
  • Use rotation speed 0 when staging a multi-step update if you want to avoid visible in-between frames.

PLC Integration Notes

  • Treat this as a zero-based holding-register map in your PLC tag layer.
  • For deterministic scan behavior, group related writes into one FC10 transaction whenever possible.
  • If your PLC uses 40001-style addressing, apply your driver offset so it targets register 0-99 on this device.

Commissioning tip: Start with FC06 for step-by-step verification, then migrate to grouped FC10 writes for production scan stability.
